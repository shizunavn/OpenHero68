# Macro editor

The Macros page keeps an editable computer-local library, independent of onboard profile slots. When HERO68 is connected, **Save macro** also serializes the complete non-empty macro library and writes it to the keyboard with the recovered v3 `CMD 0x05` protocol. It supports creating, renaming, duplicating, removing (with undo), searching, importing/exporting, recording keyboard events, editing press/release events and delays, changing event order and preparing playback settings. Drafts survive navigation and reload; switching away from an edited sequence offers save/discard/cancel.

Record keys appends to the sequence. Keyboard input is captured only in the focused recording area. Escape/Tab, moving focus away and the event limit stop recording; held keys receive zero-delay release events. System-reserved shortcuts may need manual entry. “Add keystroke” inserts a paired press/release; single events are in a disclosure. Delay is the wait **before** an event. Preview animates one cycle and does not dispatch events or send OS input. Saving validates balanced key states so malformed sequences cannot enter the saved library.

Storage uses `openhero68:macro-library:v1` for saved definitions and `openhero68:macro-draft:v1` for the current draft. Limits of 64 definitions, 512 events and 60 seconds per delay are editor limits, not firmware capacity claims. JSON imports are validated, appended with fresh IDs, and never replace existing macros.

The 108-action catalog is taken from the recovered official controller artifact `hero68_re/docs/static_bundle_catalog.json`, including keyboard and mouse action metadata. Native recording captures keyboard events; mouse buttons can be added manually.

On-device macro writing now mirrors the official v3 controller recovered from `_transfer_macro_to_raw_data()`, `_sync_macro()` and `_send_macro_to_device()`: each event is four bytes (`action high nibble + duration[19:16]`, `duration[15:8]`, `duration[7:0]`, action value); every macro entry is `nameLength:u8 + UTF-8 name + events`; a little-endian `{offset:u16,length:u16}` table precedes all entries; and the result is fragmented into 56-byte `CMD 0x05` reports. Each report must be echoed byte-for-byte by the device before the next fragment is sent. The editor's `delayMs` maps directly to the official 20-bit `duration` field.

`hello.pcapng` was captured from creating `hello`, typing `zxcvbnm,./`, adding/clicking `MouseKey0`, and pressing the official editor's Save button. That trace contains the ordinary keyboard/mouse input reports but **no HERO68 vendor-HID OUT report**, confirming that editor Save itself does not perform the device write. Static controller code shows `CMD 0x05` is invoked when macro-bearing key data is synchronized. OpenHero68 deliberately exposes the recovered blob write on **Save macro** so definitions can already be staged on the keyboard before macro-key assignment UI is implemented.

There is still no recovered macro-definition read command, so the local library remains the editable source of truth and the page cannot hydrate definitions back from an arbitrary keyboard. Playback behavior (`once`/repeat/hold/toggle) is not part of `CMD 0x05`; the official controller stores the behavior, count and macro index in the six-byte macro key-mapping record written by `CMD 0x03`. Key assignment and physical playback therefore remain a separate integration step. An empty official macro list sends no `CMD 0x05`, so deleting the final local macro is not claimed to erase onboard macro storage.

Tests cover held-key balance, partial drafts, export/import, duplicate IDs, invalid timing/playback/actions and catalog metadata. Browser QA covers recording/stop, local save/reload, manual edits, preview, draft switching and deletion undo.
