# OpenHero68 RGB Service v0.3.0

Rhythm Sync now captures Windows system audio in the native helper and drives
the HERO68's 68 key LEDs. Custom Effects and Rhythm Sync share a 60 FPS native
HID scheduler with whole-frame batches, bounded queues and coalesced previews.

- Key modes: Dazzling Rock (169), Clouds (170), Light Field (171), Gurgling
  Stream (172), Blooming Passion (173), Dynamic Spectrum (428), and Off (180).
- Default or fixed WASAPI playback endpoint, immediate attack, adjustable
  sensitivity, brightness, palette and release smoothing. Spectrum uses the
  latest overlapping audio window; browser activity is outside the audio-to-LED path.
- Rhythm Sync has mode cards, an encoded-color preview, audio meter and live
  session-bound edits. Opening a tab or selecting a card only changes the draft.
  Apply starts playback, which continues after closing the browser.
- Without a compatible service, Rhythm uses the same blurred setup gate as
  Custom Effects. Try demo appears only in that gate and uses labeled synthetic
  audio. The normal action row contains Apply and Return to onboard.
- Intermittent profile-selection timeout recovery reads back the active slot
  after a missing ACK and retries only the same idempotent selection. Direct
  WebHID transactions are serialized across tabs; service batches use the same recovery.
- Saved Rhythm and Custom presets stay separate. Tray Start saved RGB resumes
  the last saved mode. Configuration batches pause playback while writing settings.

## Install / upgrade

**Download the full Windows x64 ZIP.** Quit the old tray app, extract every file
over its folder, then run `Hero68RgbService.exe`. Keep all included files together.
This release requires **core 0.3.0, launcher 0.3.0 and API 5**; the native audio/HID
helper changes, so a core-only update is insufficient. If Auto-start references
another folder, choose **Auto-start: replace old app path** in the new tray.
Auto-start remains optional. No Node/Python installation is needed for the ZIP.

Windows 10 1703+/11 and a wired HERO68 are the supported verification setup.
The new Rhythm editor is included in the source; publishing this GitHub release
does not deploy the hosted web app. Build/serve this source for the new UI until
the hosted app is updated.

## Verification and limits

All **451 automated tests**, web build, native build, native DSP/protocol tests
and real WASAPI stereo audio probe passed. UI checks covered service/demo gates,
Apply, stale sessions, live edits, keyboard controls and a 480 px viewport.

A ten-minute wired HERO68 benchmark ran four 150-second phases:

| Mode | Hall | Completed OS-write FPS | Frame gap p95 | Timeouts | Dropped frames |
| --- | --- | ---: | ---: | ---: | ---: |
| Custom Aurora + Scan | Off | 60.00 | 17.47 ms | 0 | 0 |
| Custom Aurora + Scan | 10 keys | 60.00 | 17.53 ms | 0 | 0 |
| Native Spectrum | Off | 60.00 | 17.20 ms | 0 | 0 |
| Native Spectrum | 10 keys | 60.00 | 17.09 ms | 0 | 0 |

These measure host write completion, not LED readback. Capture receipt to
completed USB write p95 was 9.18 ms with and without Hall. The packaged build
also passed a final USB smoke check after telemetry and timeout-recovery fixes.

**Live side rhythm remains disabled** until LED count, order, channel order,
commands and restoration are verified on hardware. Side 500 leaves the onboard
effect running; 501/502/503 are available in illustrative demo only.

**Sample-to-write p95 <=35 ms and physical audio-to-light p95 <=50 ms remain
unverified.** This endpoint sometimes reports future audio timestamps; negative
latencies are excluded and counted, not clamped to zero. Physical latency needs
a synchronized optical measurement. Preview FPS cannot establish that latency.
