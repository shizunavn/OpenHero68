# Gamepad connection and ViGEm startup fixes

Opening Gamepad no longer flashes the missing-service blur while the initial
connection check is pending. Controls stay inactive until the live service
explicitly confirms ViGEmBus. Confirmed failures still blur the whole page;
checking again keeps an existing failure overlay visible until validation succeeds.

When ViGEmBus plugs in a controller but Windows cannot finish initializing it,
the native client now actually attempts to unplug that child and preserves the
original Windows error. Previously its cleanup could report `0xe0000007`
(`TARGET_NOT_PLUGGED_IN`) before even sending an unplug request. This fixes
cleanup and diagnostics; it cannot repair a failed Windows driver stack.
If startup still fails, retry Start, and restart Windows if it persists after
installing the official ViGEmBus driver.

Install the full Windows 0.4.2 package for the native client fix. Its signed core
requires launcher 0.4.2, ensuring older installations receive the full-package
update rather than only JavaScript. Stop Gamepad and quit the service before
replacing files. The Cloudflare Pages ZIP contains the corresponding web fix.

Validation: production web and Windows builds, access-gating tests, fake-driver
tests covering successful startup, Windows readiness failure, cleanup failure
and legacy compatibility; browser checks with a delayed service, a missing
driver and a retry. No live controller or keyboard input was injected.
