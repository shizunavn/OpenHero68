# OpenHero68 service v0.5.2

- Fix intermittent Custom RGB stalls when combining Aurora, Scan and Pressure
  Wave. Native stdout writes now run on a dedicated writer thread, so a slow
  service reader cannot block the RGB timer. Reply and key event queues are
  bounded; stale telemetry is replaced with its latest value.
- Send due lighting frames before starting another blocking Hall request, and
  retain the latest sample for every subscribed key when Hall snapshots merge.
- Reduce Custom RGB rendering work by caching palettes and Scan bounds and
  skipping hidden firmware key animation when Aurora replaces the base.
- Preserve frame totals and long-gap statistics across merged telemetry, and
  expose native timer and IPC queue statistics through service status.

Validation: the full repository test suite, web build, native queue tests and
MSVC service build passed. The setup signature and SHA-256 were verified. In a
hardware-free probe, blocking stdout for 350 ms
preserved all 73 native timer ticks and 2,000 command replies; the maximum tick
gap was 17.2 ms. Shutdown with blocked stdout also passed.
Isolated setup smoke tests passed installation to a Unicode path, two full
updates, restart, health rollback, interrupted-update recovery, data
preservation and uninstall.

The native bridge repeats the most recent frame while the service is delayed.
This fix prevents stdout backpressure from blocking the native timer; animation
still depends on the service producing fresh frames. API version remains 6.
