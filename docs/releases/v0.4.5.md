# Gamepad startup, drag removal and RGB workspace

Mapped controller controls can now be dragged from the keyboard onto the
mapping panel or anywhere outside the keyboard to remove them. The drag preview
shows "Drop to remove binding" in red. Dropping onto another key moves the
binding and preserves its analog travel settings; cancelling the drag keeps
the mapping. Changes continue to save and apply automatically.

RGB's Onboard, Custom and Rhythm editors now share a toolbar and preview panel,
with current lighting output, Start/Back to onboard controls, sync notices and
draft recovery together. Custom base effects use a separate chooser; layer LED
selection and per-key painting controls sit below the keyboard preview. RGB
previews hide Advanced Key badges, retain side-light preview frames and include
the updated Vietnamese effect and status labels.

ViGEmBus 1.22.0's ready request gives Windows one second to initialize the
virtual Xbox device. Slow initial xusb enumeration can exceed that window and
return Windows 483. The native client now retains the same child for up to ten
additional seconds and repeats the driver's readiness wait on the same serial.
It does not declare success for a timeout, failed wait or permanent driver
error. Failure still unplugs the
child and preserves the actual Windows error.

Xbox Start now has a 15-second native watchdog and a 30-second browser request
window. Ordinary HID commands keep their 2-second watchdog and status/config
requests keep their 5-second deadline. This prevents the service from killing
an otherwise healthy helper while Windows finishes cold initialization.

Startup also identifies its own XInput slot using a tiny four-axis bootstrap
report before immediately neutralizing it. ViGEm's user-index query can return
no output and incorrectly label another connected controller as player one;
the adapter now verifies its own device instead. No buttons or triggers are
sent by this bootstrap, and the axis values are below standard deadzones.

The complete Windows ZIP is required: **launcher/native helper 0.4.5**.
The signed core requires launcher 0.4.5 so older installations are offered the
full package instead of a JS-only update that would leave the old native code.
ViGEmBus remains a separate driver installation.

Validation: production web and Windows builds, 533 JavaScript regressions, signed
core and ZIP checksum/entry verification. Native simulated-bus tests cover
delayed boot on one target, bounded timeout, immediate
and asynchronous fatal errors, cleanup failure and pre-1.17 compatibility.
Service integration delays native Start for 5.2 seconds and verifies firmware
blocking/restoration afterward. Component drag tests cover removal, cancel,
moving analog settings, same-key/background drops and palette assignment.
Live ViGEmBus checks passed for forced timeout recovery on one target and two
warm Start/Stop cycles. With another controller occupying slot 0, the new
target was correctly verified at slot 1 with all actual controls neutral.

The machine's first post-reboot initialization has not been reproduced by these
simulations. Persistent Windows driver faults cannot be guaranteed away by a
user-mode change; a failed initialization still returns an error.
