# OpenHero68 RGB Service v0.3.1

Fixes **Check for updates** failing with `Unexpected update source` after the
GitHub repository was renamed from `OpenHero68-RGB-Service` to `OpenHero68`.
The old API address redirects successfully, but GitHub returns asset URLs under
the new name; the previous updater rejected those URLs before downloading.

The updater now queries the canonical repository and accepts release-download
paths under both known names. Signature checks, package checksums, size limits
and the source allowlist remain enforced. Tests cover signed core updates, full
Windows ZIP updates, the original alias, and rejection of lookalike URLs.

**If you have 0.2.3 or 0.3.0, download this full Windows x64 ZIP manually once.**
The old updater cannot download the fix for its own URL rejection. Quit the old
tray app, extract every file over its folder, and run `Hero68RgbService.exe`.
Keep all files together; presets are stored separately and retained.

Package core/launcher: **0.3.1**, API **5**. A compatible 0.3.x native installation
can run the signed core; upgrading from 0.2.x needs the full package. Auto-start
remains optional; replace its app path in the tray if you move the folder.

Rhythm algorithms and 60 FPS rendering are unchanged from 0.3.0. Live side
rhythm and sample/physical audio-to-light latency remain unverified as described
in the 0.3.0 release notes. Publishing this GitHub release does not deploy the UI.

Validation: **453 automated tests passed**, service typecheck and native build
passed, and the signed core/full ZIP were verified against the packaged files.
A live GitHub check downloaded the canonical-name release with a simulated
0.2.3 installation and validated the signed manifest and Windows ZIP checksum.
